题目链接： [NOI 2026] 布丁 。

题目描述：

有多次询问，每次询问交互库会生成一个数 www ，你需要实现函数 int find_tastiness(int c,int m) 猜测并返回这个 www 。

你可以调用函数 int query_tastiness(vector<int>S) ，该函数会将 www 加入 SSS 后排序并输出相邻两项的 gcd⁡\gcdgcd 之和。

对于单组测试，你最多调用不超过 444 次该函数，传入的 SSS 最多不超过 353535 。如果你超过了限制，你会获得相应的部分分。

w∈[1,m],m=3000w\in[1,m],m=3000w∈[1,m],m=3000 。

时间限制 12s12s12s 。

交互库不是自适应的。

很明显 gcd⁡\gcdgcd 的和不具备任何实际意义。你只能通过 query_tastiness 的结果和原来的 SSS 的相邻两项 gcd⁡\gcdgcd 做差才能得到有效信息。不妨设 query(S) 的结果为这个信息。

容易发现如果我传入序列 S={1,2,3,⋯ ,m}S=\{1,2,3,\cdots,m\}S={1,2,3,⋯,m} ，那么 query(S) 的结果就是 www 。这样做可以获得 161616 分。

考虑调用 444 次 query ，前三次缩小 SSS 的范围，最后一次直接传入 SSS 。

一个简单的想法是随机 KKK 个长度为 nnn 的序列，手动计算对于每一个 w=iw=iw=i ， query 的值。找到这 KKK 个序列中最能区分的序列，然后询问。复杂度 O(Knm)\mathcal{O}(Knm)O(Knm) 。由于常数原因，取 n=9,K=10n=9,K=10n=9,K=10 后获得 505050 分。

考虑优化。很明显如果 KKK 能更大，分数肯定更高。所以我们考虑优化常数。容易发现对于相同的 SSS ，我们其实重复计算了几乎 mmm 遍，所以考虑记忆化序列。我这里采用自然溢出哈希和 unordered_map 存储。在 n=9,K=2000n=9,K=2000n=9,K=2000 时获得了 868686 分。

然后就是一些调参工作了。目前这样最高有 979797 分，参数 n=6,K=4100n=6,K=4100n=6,K=4100 。

然后就是一些神人优化了。参考 NOI 2024 百万富翁，这题本质上是提交答案题，于是考虑打表。

具体来说，虽然我直接设置 K=105K=10^5K=105 会超时，但是我可以本地多跑几趟 K=4700K=4700K=4700 ，然后根据表找到更优秀的初始序列就行。这种方法最终使得调用 query 的 SSS 的和为 353535 ， 通过了 100100100 分。

其实这种方法的上限远不止于此：

  1. 可以本地多跑几趟，获得更优秀的初始序列。
  2. 可以换成更优秀的随即方式。
