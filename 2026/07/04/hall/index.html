15pts15pts15pts ：暴力树形 DP

有些题目，像这题，即使是最朴素的暴力 DP 也很难想。

首先，这个题目的决策点是树上的每个点，而决策是选择休息或冲刺。

那么自然可以得出第一个状态设计： fif_ifi​ 表示 iii 冲向 111 的方案数。

那么按照决策，分两种情况：

  1. 冲刺。这种情况下需要冲刺到 [max⁡{li,hi+1},ri][\max\{l_i,h_i+1\},r_i][max{li​,hi​+1},ri​] 级祖先。方案数为 ∑合法祖先FfF\sum\limits_{合法祖先 F}f_F合法祖先F∑​fF​ 。
  2. 休息。这种情况需要累加所有儿子的方案数，即 ∑u∈sonifu\sum\limits_{u\in son_i}f_uu∈soni​∑​fu​ 。但是由于有 hih_ihi​ 的限制，下一次冲刺必须冲刺到 di−hi−1d_i-h_i-1di​−hi​−1 及以上的位置，此时无法转移。

所以我们要加一维。定义 fi,jf_{i,j}fi,j​ 表示从节点 iii 出发，冲向 111 且下一次冲刺到深度 jjj 的方案数。

设 iii 的深度为 jjj 的祖先为 xxx 。

接着按照决策，分三种情况：

  1. jjj 不合法，即 di−hi≤jd_i-h_i\le jdi​−hi​≤j 。这种情况下 fi,j=0f_{i,j}=0fi,j​=0 。
  2. 在 jjj 合法时，冲刺。此时需要满足 di−ri≤j≤di−lid_i-r_i\le j\le d_i-l_idi​−ri​≤j≤di​−li​ 。这种情况方案数为 ∑kfx,k\sum\limits_{k}f_{x,k}k∑​fx,k​ 。
  3. 在 jjj 合法时，休息。此时可以滑落至任意一个儿子。这种情况的方案数为 ∑uu∈sonifu,j\sum\limits_{uu\in son_i}f_{u,j}uu∈soni​∑​fu,j​ 。

然后又会发现，这样转移似乎有后效性，因为一个点会从他的祖先和儿子同时转移而来。

但仔细想后就会发现，其实每个点只会从他的儿子转移，于是从下到上合并儿子转移就行。这是因为对于祖先的转移是 fx,k,k<jf_{x,k},k<jfx,k​,k<j ，因为 xxx 无法冲刺到它本身。

于是我们对着 jjj 这一维顺序树形 DP 就行。

25pts25pts25pts ：暴力线段树合并优化树形 DP

暴力部分结束了，接下来是优化 DP 。

首先，优化 DP 一般有两种：一种是改变状态优化，一种是利用 DP 的结构性质优化。

这个 DP 显然状态设计上无法优化，于是只能通过观察 DP 的结构性质。

一般的一个观察是抛弃 fff 数组，直接利用 DP 结构进行优化，但很可惜这是无法优化的（至少我没想到）。

错误的思路：

考虑刻画 DP 结构。容易发现这个 DP 的结构本质上是对于每个 jjj ，每个 iii ，若 jjj 对于 iii 合法且 iii 可以冲刺到 jjj ，则找到最小深度的祖先 xxx 满足 jjj 对于 iii 到 xxx 路径上的点合法，将路径上的点的 sumsumsum 累加上 iii 深度为 jjj 的祖先 yyy 的权值 sumysum_ysumy​ 。

可惜到这一步为止了，无法进一步优化。

刻画 DP 结构本质是不可能了，只能找到一些可以优化的地方进行优化。

我们发现 fi,jf_{i,j}fi,j​ 转移时，会将子节点 uuu 的 fu,jf_{u,j}fu,j​ 累加，这很像线段树合并。

进一步的，对于叶子节点，他们不能休息，只能冲刺。那么对于叶子 iii ， fi,jf_{i,j}fi,j​ 在一段区间里面有值。那么对于任意节点 iii ， iii 里面最多只有 sizisiz_isizi​ 个区间（可重叠）有值，这正好对应线段树区间加和区间合并。

这引导我们去线段树合并。

但是这样做又有一个问题：直接合并就不能按 jjj 的顺序转移了，又有后效性了。

此时又需要一个极为 tricky 的想法（ How have I thought out this tricky method? ）：系数。

我们发现，对于 iii ，设他的深度 jjj 的祖先为 xxx ，那么对于任意一个 iii 子树内的节点 uuu ， iii 必然由 uuu 转移而来，同时 iii 和 uuu 都有 xxx 转移而来，即， fi,j=Ksumxf_{i,j}=Ksum_xfi,j​=Ksumx​ 。

当我们不按照 jjj 得顺序转移时，虽然我不能直接转移 fi,jf_{i,j}fi,j​ ，但是前面的那个系数 KKK 与 xxx 无关，可以不按照 jjj 的顺序转移。那么我们就可以成功的线段树合并转移出系数。

对于每个点 iii ：

  1. 先累加 iii 自己的贡献，也就是 [di−ri,min⁡{di−hi−1,di−li}][d_i-r_i,\min\{d_i-h_i-1,d_i-l_i\}][di​−ri​,min{di​−hi​−1,di​−li​}] 的位置，每个位置上的数 +1+1+1 。
  2. 然后区间合并儿子，具体就是只合并区间 [1,di−hi−1][1,d_i-h_i-1][1,di​−hi​−1] 的位置。

这里面还有一个小细节，就是线段树合并不好处理区间加，这里可以用差分代替。但是注意，由于 fi,jf_{i,j}fi,j​ 有值的地方仅限于 [1,di−hi−1][1,d_i-h_i-1][1,di​−hi​−1] ，也就是说，最后需要将区间 [1,di−hi−1][1,d_i-h_i-1][1,di​−hi​−1] 的和在 di−hid_i-h_idi​−hi​ 减去，不然会影响到 iii 的父节点的合并。

这样就完成了系数 KKK 的合并。

接下来就是还原 fi,jf_{i,j}fi,j​ 的值。这一点可以通过自上而下还原。因为 xxx 一定永远是 iii 的祖先，在转移 iii 时， xxx 必定被转移完了，所以无后效性。而且这里只需要维护和就行了，正好答案也求的是和，十分匹配。

具体来说就是遍历每个节点的线段树，同时累加前缀和。每到一个叶子节点，用前缀和加上叶子权值得到的结果与对应 sumxsum_xsumx​ 相乘后返回。每到一个空节点，用前缀和乘上 sumsumsum 的对应区间和就行。因为我们不关心具体值，只在意和。

然后就完成了。于是你自认为 AC 了此题。

分析一下复杂度：线段树合并是 O(nlog⁡n)O(n\log n)O(nlogn) 的，遍历是 O(n2)O(n^2)O(n2) 的（不要像我一样想当然的认为是 O(nlog⁡n)O(n\log n)O(nlogn) 的），常数比普通的大许多，但是实际前 555 个点表现优秀。

其实做出上一步已经很难了（我是怎么在半小时内想出上面的部分的？），如果上面的做出来了，这一步也不难。

容易发现复杂度瓶颈在 relax 函数的遍历。但是理论上线段树合并的遍历和这个遍历，或许是差不多的。

但是实际上一个 O(n2)O(n^2)O(n2) 一个 O(nlog⁡n)O(n\log n)O(nlogn) 。

Recall\text{Recall}Recall 线段树合并的过程，为什么这个复杂度是 O(nlog⁡n)O(n\log n)O(nlogn) ？原因是线段树合并过程中出现了节点公用，即一个节点同时存在于多棵动态开点线段树，由 if(!p||!q)return p+q; 这里看出。

那么这个也意味着，如果 relax 函数中，一个节点每次被访问的贡献一样，那么我就可以记录下他的贡献，下次遇到是直接返回，这样复杂度就也是 O(nlog⁡n)O(n\log n)O(nlogn) 了。

至于每次进来时的贡献，容易发现这个节点本身的贡献是平凡的，这里指这个线段子树内的贡献，不包含这个数以前的前缀和贡献（即 mx ）。这是因为这个点线段子树内的权值一样，而会共用节点的线段树必然在树上构成祖孙关系，也就是说，属于同一个位置的数的那个 s[l]-s[l-1] 是一样的。

然后就是那个前缀和 mx 的贡献了。容易发现这个 mx 的贡献永远是 mx 所代表和的右侧的数的对应的 s[l]-s[l-1] 的贡献，使用乘法分配律得到 mx 贡献为 mx*(s[r]-s[l-1]) ，因此这一部分也是平凡的。

于是我们就解决了这道 NOI2024 的黑题（ D2T2 ），还是挺不错的一道题目。
